# 設計メモ

## 目的

日本語話者が英語の可算・不可算名詞を、日本語との違いを意識しながら学べるクイズを提供する。単語帳的な暗記ではなく、語義と用法の判断を短いセッションで繰り返す。

## 対象と前提

- 日本語を母語とする英語学習者（中学〜大人）
- スマートフォンとデスクトップの両方
- アカウント不要。学習履歴は端末内のみ
- v1 では SNS 共有、連続学習日数、分野フィルターは扱わない

## 難易度

日本語との距離を基準に4段階へ分ける。

| レベル | 内容 | 例 |
| --- | --- | --- |
| L1 | 具体的な物質・液体・素材、基本の可算名詞 | milk, salt, book, chair |
| L2 | 抽象名詞、学問・感情・ビジネス | information, advice, idea, success |
| L3 | 語義によって可算性が変わる語 | paper（紙／新聞）, water（水／水域） |
| L4 | 日本語話者が複数形にしがちな語 | furniture, luggage, equipment, news |

L1・L2 は「その語の代表的な用法」を問い、L3 は語義ごとの判断、L4 は日本語とのズレが大きい語を重点的に扱う。

### 語数の配分

- L1: 200
- L2: 300
- L3: 200
- L4: 100
- 合計: 800

`scripts/build-dataset.ts` が最終的な件数を検証し、800 語でなければ失敗する。`both` の語は必ず2つ以上の語義（可算・不可算）を持ち、L3 にのみ配置する。

## 出題

1セット10問。同じ語は1回だけ。

| 種類 | 比率 | 内容 |
| --- | --- | --- |
| 可算性の判定 | 50% | 語（L3 では語義）に対して可算／不可算／両方を選ぶ |
| 空所補充 | 35% | `How ___ milk do you need?` に much / many などを入れる |
| 誤り訂正 | 15% | `a furniture` / `many informations` などから正しい形を選ぶ |

10問では 5 / 3.5 / 1.5 が理想のため、空所補充と訂正の端数をセッションごとに交互へ振る。`both` の語や集合名詞は空所補充・訂正に向かないので判定問題へフォールバックする。

### 出題順

- シード付き乱数で再現可能にする
- 直近24時間に解いた語はプールの後ろへ回す
- 復習モードでは、直近の回答が不正解の語だけを対象にする
- 対象語が10未満なら、その語数だけ出題する

## 画面とルーティング

TanStack Router のファイルベースルーティング。ベースパスは `/kasan/`（`BASE_PATH` で変更可）。

| パス | 役割 |
| --- | --- |
| `/` | 難易度選択、学習状況、ヒント |
| `/quiz/$difficulty` | `L1`〜`L4` / `all` / `review` のクイズ |
| `/result` | 直近セッションの結果と問題別の振り返り |
| `/review` | 間違えた語の一覧、復習の開始、履歴リセット |
| `/licenses` | 出典・ライセンス |
| `/about` | 使い方、難易度、データの注意事項 |

GitHub Pages の直接アクセス用に、ビルド後に `dist/index.html` を `dist/404.html` へ複製する。`public/.nojekyll` も配置する。

## 状態管理

- クイズ進行中: `sessionStorage` に保存し、同じ難易度なら再読み込み後に再開
- 学習履歴: `localStorage` の `kasan:progress:v1`
  - 語ごとの正解・不正解回数、最終回答日時
  - 直近30セッションの記録
- 結果画面: `localStorage` の `kasan:last-result:v1`

サーバー送信は行わない。保存に失敗してもクイズは継続できるようにする。

## アクセシビリティ

- 正誤は色だけでなく、アイコンと文字（「正解」「不正解」）でも示す
- 選択肢は実ボタン。回答後は正解・自分の回答をラベルで明示
- キーボード: `1` / `2` / `3` で回答、`Enter` で次へ
- 進捗と正答率に `aria-label` を付与
- フォーカスリングは shadcn のデフォルトを維持

## データパイプライン

1. FrequencyWords（MIT）の頻度リストから候補語を取る
2. 英語版 Wiktionary のウィキテキストを取得し、`{{en-noun|...}}` と `{{lb|en|...}}` ラベルを解析
3. Wikidata の日本語ラベルを取得（CC0、429 時は待機）
4. `data/curated/` の手作業データを優先し、L1 の不足分だけを自動抽出語で補う（現在は 731 語がキュレーション、69 語が自動）
5. 語義・解説パターン・出典を付与し、zod スキーマで検証
6. `src/data/words.json` と `src/data/meta.json` を出力

自動抽出は Wiktionary のラベルに依存するため、`both` の判定が広すぎたり、具体名詞と抽象名詞の区別が崩れたりする場合がある。そのため L2 と L3 はキュレーションした語だけにし、L4 もキュレーションで固定する。自動抽出語は L1 の具体的な名詞の不足分（69 語）だけに使い、不適切な語は `SKIP_AUTO` で除外する。

## 非目標（v1）

- ユーザーアカウント、クラウド同期
- SNS 共有画像、ランキング
- 分野別フィルター、連続学習日数
- E2E テスト
- 音声読み上げ

## 検証

- `bun check`: TypeScript 7
- `bun run fmt:check`: oxfmt
- `bun run lint`: oxlint
- `bun test`: データ件数・スキーマ・代表語の判定・クイズ生成・出題比率・重複・直近語の扱い
- `bun run build`: Vite ビルドと `404.html` 生成

CI は mise で Bun を固定し、PR で lint → 型チェック → テスト → ビルドを実行する。`main` への push で GitHub Pages へデプロイする。
